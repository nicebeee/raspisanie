# Расписание техникума

Веб-приложение для составления расписания на каждый день: учитывает доступность преподавателей, закреплённые аудитории, деление групп на подгруппы и ведёт учёт оставшихся пар по учебному плану.

## Запуск

Нужен Node.js 22.13 или новее (внешние пакеты не нужны, база — встроенный SQLite).

```
npm start
```

Откройте http://localhost:3000. При первом запуске создаётся база `data/raspisanie.db` с демо-данными (3 группы, 7 преподавателей, черновик расписания на ближайший учебный день). Чтобы начать с чистого листа, остановите сервер и удалите папку `data`.

Порт и путь к базе можно поменять: `PORT=8080 DB_FILE=/путь/к/base.db npm start`.

Тесты правил: `npm test`.

## Вход

Без входа виден только утверждённый план занятий: неделя для группы, преподавателя или аудитории, на телефоне — по дням. Кнопка «Войти» открывает для администратора весь интерфейс.

Пароль администратора:
- задаётся переменной `ADMIN_PASSWORD` (на хостинге) — она главнее пароля, сменённого в интерфейсе;
- если переменной нет, при первом запуске создаётся случайный пароль: он печатается в консоли и сохраняется в `data/admin-password.txt`. Сменить его можно в «Настройках».

## Публикация

- **Render** (бесплатно): New → Blueprint → выбрать этот репозиторий, задать `ADMIN_PASSWORD`. Настройки уже в `render.yaml`. На бесплатном тарифе диск не сохраняется: после простоя 15 минут или нового деплоя база возвращается к демо-данным. Для постоянной работы нужен платный тариф с диском, `DB_FILE` должен указывать на этот диск.
- **Любой сервер с Docker:** `docker build -t raspisanie . && docker run -p 3000:3000 -e ADMIN_PASSWORD=... -v raspisanie-data:/data raspisanie`.

## Что умеет

- **Расписание на день** — сетка «группы × пары 1–6». Ячейку можно заполнить для всей группы или по подгруппам. Пару можно перетащить на другое время внутри группы. Справа — список ошибок и предупреждений; утвердить день можно только без ошибок.
- **Проверки:** не более 4 пар и без окон (для каждой подгруппы отдельно, её пары + общие пары группы); преподаватель — только в свои дни и пары и не в двух местах сразу; аудитория — не занята дважды; преподаватель с закреплённой аудиторией ставится только в неё; лабораторные/практические, отмеченные «по подгруппам», нельзя ставить всей группе; предупреждения о вместимости, типе аудитории и превышении часов.
- **Учебный план** — по каждой группе: предметы, часы (всего, лекции, практические, лабораторные), проведено и осталось пар. Пары списываются при утверждении дня, отмена пары возвращает её в остаток. Для занятий по подгруппам счётчик ведётся на каждую подгруппу.
- **Преподаватели** — доступность по дням недели («с … по … пару»), закреплённая аудитория, отсутствия (больничный, командировка, отпуск).
- **Аудитории, группы, подгруппы, предметы** — справочники.
- **Просмотр** — неделя для группы, преподавателя или аудитории; печать.
- **Нагрузка** — часы преподавателей по плану, проведено, за месяц.
- **Настройки** — звонки, лимит пар в день, часов в паре; журнал изменений.

## Чего пока нет (по ТЗ — следующие этапы)

- отдельные учётные записи для нескольких диспетчеров (сейчас один общий пароль администратора);
- автоматическое заполнение дня;
- импорт из Excel и выгрузка отчётов в Excel;
- для продакшена с несколькими диспетчерами стоит перейти на PostgreSQL и Docker.

## Устройство

- `server.js` — HTTP-сервер и раздача страниц.
- `lib/db.js` — схема базы и демо-данные.
- `lib/logic.js` — правила проверки расписания и подсчёт остатка пар.
- `lib/api.js` — API (`/api/...`).
- `public/` — интерфейс (HTML, CSS, JS без сборки).
- `test/` — тесты правил.
